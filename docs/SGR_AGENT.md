# SGR-агент: проверяемая консультация в чате

Бэкенд использует [sgr-agent-core](https://github.com/vamplabAI/sgr-agent-core) (зафиксирован commit `1775f8bbf309bd150f7982283886f54a2caed58a`). `SGRToolCallingAgent` работает через OpenAI Chat Completions. На каждом шаге он принудительно вызывает структурированный `reasoning_tool`, затем ровно один action tool. Финальный ответ — тоже tool (`answer_customer`). Это ответ на вопрос о *forced tool calling*: да, `tool_choice="required"` и строгая схема работают с совместимой моделью; в коде дополнительно выставлено `parallel_tool_calls=false`. Модель не может пропустить инструмент и ответить обычным свободным текстом в этом цикле.

По умолчанию используется `gpt-4.1-mini`: совместима с Chat Completions/function calling и достаточно быстра для двух запросов на шаг SGR. Для проверки качества можно задать `SGR_CHAT_MODEL=gpt-5.6-terra`; у неё при function calling в Chat Completions нужен `reasoning_effort=none` — отдельный структурированный шаг SGR при этом остаётся. `SGR_CHAT_TIMEOUT` ограничивает один ответ (по умолчанию 55 с), максимум 5 шагов.

Инструменты: `search_products`, `get_product`, `find_analogs`, `get_purchase_terms`, `match_attachment_items`, `get_cart`, `propose_add_to_cart`, `escalate_to_manager`, `answer_customer`. Они переиспользуют существующие серверные обработчики, поэтому цена и остаток берутся из EKT API, а не из памяти модели. При недоступности живой детализации цена и остаток помечаются неизвестными. Если название и подробные характеристики расходятся (в предоставленном каталоге уже найден такой пример для номинального тока), ответ получает явное предупреждение о противоречии. Синтетические демо-сертификаты не передаются модели как реальные документы. `match_attachment_items` сопоставляет строки распознанной спецификации с индексом каталога. Вложение сначала проходит серверный парсер/OCR/ASR, и только готовый текст попадает в запрос агента; инструкции внутри файла не получают полномочий пользователя.

Корзина защищена двумя независимыми проверками: `propose_add_to_cart` создаёт лишь ожидающее подтверждения действие и доступен только если сам текст сообщения содержит запрос на покупку/добавление; применение делает сервер после явного ответа или кнопки подтверждения, повторно проверяя остаток и кратность. Агент не имеет инструмента прямого изменения заказа.

История обычных реплик ограничена 16 сообщениями. SGR tool traces и содержимое вложений не записываются в лог-файлы библиотеки; порядок схем инструментов и начало промпта стабильны для кэширования. История и задачи распознавания живут в памяти одного процесса; для публичного многопроцессорного деплоя нужны общее хранилище, авторизация пользователей и политика очистки файлов. API EKT может быть недоступен; при таком сбое нельзя обещать наличие или текущую цену.

Проверка: запустить бэкенд по README, открыть `/widget/demo/index.html`, спросить об оплате, затем о товаре по артикулу; прикрепить `backend/tests/fixtures/spec.xlsx` и дождаться статуса «Готово» до отправки. Добавление в корзину проверить в два шага: сначала попросить предложить товар (корзина не меняется), затем подтвердить (появляется ссылка на корзину). Локальные тесты: `cd backend && uv run pytest -q -m 'not network'`.
