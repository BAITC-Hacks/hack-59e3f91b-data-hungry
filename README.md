# ИИ-ассистент для сайта ekt.kz — команда Data Hungry (Hackalem AI)

Кейс №1 ТОО «Электрокомплект»: ассистент в чате на сайте, который консультирует по каталогу (наличие, характеристики, сертификаты, аналоги, условия покупки) и добавляет товары в корзину только после явного подтверждения клиента.

**Статус (23.09.2026):** прототип собран и запускается локально (см. «Запуск прототипа» ниже). Что в репозитории:

- `backend/` — FastAPI-бэкенд: индекс каталога (SQLite FTS5), живые остатки через API ekt.kz, база знаний по условиям покупки, разбор вложений, агент на Claude (tool use), корзина с подтверждением.
- `widget/` — встраиваемый чат-виджет (один `<script>`, Shadow DOM, десктоп и мобилка).
- `docs/API_CONTRACT.md` — контракт API бэкенд ↔ виджет; `docs/FRONTEND.md` — спецификация виджета и сценарий демо.
- `docs/VM.md` — способ подключения к предоставленной GPU VM и команда проверки H200.
- `scripts/`, `reports/` — аудит каталога (этап подготовки данных, см. ниже).

## Запуск прототипа

```bash
cd backend
uv sync --extra dev
uv run python scripts/build_index.py --dump ../../probe/dump   # data/catalog.sqlite (15 035 SKU из списка API)
cp .env.example .env                                           # впишите ANTHROPIC_API_KEY (необязательно, см. ниже)
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Дальше открыть:
- http://localhost:8000/widget/demo/index.html — имитация карточки товара ekt.kz с виджетом (панель открыта сразу);
- http://localhost:8000/api/health — `{ok, products, model, llm_configured}`;
- http://localhost:8000/docs — OpenAPI.

Тесты: `cd backend && uv run pytest -q` (64 теста; помеченные `network` ходят в живой API ekt.kz).

**Без ключа Anthropic** работает всё, кроме свободного диалога: `/api/products/search`, `/api/products/{id}`
(остатки по складам, характеристики, сертификаты), загрузка файлов, корзина, кнопка «Добавить в корзину» в виджете
(создаёт предложение), «Подтвердить» / «да, добавь» (применяет его с ограничением по остатку и кратности) и страница
корзины. `/api/chat` отвечает короткой заметкой, что ключ не задан. Сам цикл LLM проверен офлайн скриптом с
подменённым клиентом.

Настройки (`backend/.env` или переменные окружения):

| переменная | по умолчанию | смысл |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ Anthropic (профиль `ant auth login` тоже подхватывается) |
| `LLM_MODEL` | `claude-opus-5` | модель |
| `LLM_EFFORT` | `low` | `output_config.effort`: low / medium / high |
| `LLM_FALLBACKS` | `1` | серверный fallback при отказе классификатора (beta); `0` — выключить |
| `PUBLIC_BASE_URL` | `http://localhost:8000` | база для ссылок на корзину и сертификаты |
| `DETAIL_CACHE_TTL` | `300` | сколько секунд кэшировать detail-ответы ekt.kz (остатки) |

Встраивание на ekt.kz: `<script src="https://HOST/widget/widget.js" data-api="https://HOST" data-lang="ru"></script>`;
на `*.ekt.kz` виджет дополнительно кладёт подтверждённые позиции в настоящую корзину Bitrix (см. `widget/README.md`),
букмарклет для живого сайта — `widget/bookmarklet.js`.

Сертификаты: API ekt.kz их не отдаёт, поэтому `backend/data/certificates.json` — явно помеченный **демо-реестр**
(у каждого документа `demo: true` и водяной знак DEMO на странице).

Структура бэкенда: `app/main.py` (маршруты) · `agent.py` (цикл tool use, шлюз подтверждения) · `cart.py` ·
`sessions.py` · `catalog.py` (SQLite FTS5) · `analogs.py` · `knowledge.py` · `certificates.py` · `attachments.py`
(xlsx/docx/pdf/фото) · `ekt_api.py` · `schemas.py` · `config.py`.

### Вложения и модели

В backend из локального `sdu-ai-services` перенесено извлечение текста из Office-файлов (LiteParse с запасными парсерами). Для фото и сканированных страниц PDF по умолчанию используется OpenAI vision-модель `gpt-5.6-luna`, для аудио — `gpt-transcribe`. Chandra OCR и Whisper через NITEC оставлены как переключаемый вариант (`MEDIA_AI_PROVIDER=nitec`). Существующее извлечение строк спецификации (артикул, название, количество) сохранено. Оригинал и распознанный текст хранятся в `backend/data/attachments.sqlite3` по SHA-256, типу и версии/модели обработчика; повторная загрузка использует кеш. Вложения передаются агенту как текст; фото дополнительно передаётся как изображение. Доступ к ID вложения ограничен сессией чата.

OpenAI OCR возвращает текст, но не координаты блоков; для PDF с текстовым слоем координаты извлекаются локально, а Chandra возвращает координаты для сканов. Таблицы OpenAI OCR старается передать построчно с разделителем `|`, поэтому сложная вёрстка может потребовать ручной проверки.

Модели, найденные в коде исходного `sdu-ai-services` для шлюза `llm.nitec.kz`:

| Назначение | Модель | Статус здесь |
| --- | --- | --- |
| OCR изображений/сканов | `datalab-to/chandra-ocr-2` | Доступна через NITEC при `MEDIA_AI_PROVIDER=nitec` |
| Транскрибация аудио | `openai/whisper-large-v3-turbo` | Доступна через NITEC при `MEDIA_AI_PROVIDER=nitec` |
| Общий чат и fact-check | `openai/gpt-oss-120b` | Только в исходном проекте; текущий чат использует Claude |
| Vision-метод | `Qwen/Qwen3-VL-235B-A22B-Instruct` | Настроена в исходнике, но вызовов метода не найдено |

В `sdu-ai-services` не было дедупликации по хешу содержимого — она добавлена здесь. Ключи и модели задаются через переменные окружения (пример — [`backend/.env.example`](backend/.env.example)); реальные ключи не коммитятся. Для старых Office-форматов нужен LibreOffice. Локальная SQLite и анонимный ID сессии — решение для прототипа, не замена авторизации и политики хранения персональных данных.

Запуск backend из корня репозитория (Python 3.11+, `uv`):

```bash
uv sync --locked --no-install-project --project backend
cd backend
# Создайте .env по образцу и заполните OPENAI_API_KEY; для локального стенда задайте ENABLE_FILE_LAB=1.
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [локальную лабораторию](http://127.0.0.1:8000/lab), загрузите фото, Word, Excel, PDF или аудио и сравните текст, строки спецификации и координаты. `/lab` и `/api/lab/parse` доступны только с loopback-адреса и только при `ENABLE_FILE_LAB=1`; публично включать их нельзя. На macOS без LibreOffice запасные парсеры читают DOCX/XLSX/PPTX, но старые `.doc/.xls/.ppt` могут остаться пустыми. Для OpenAI OCR/аудио нужен `OPENAI_API_KEY`; для Chandra/Whisper через NITEC — `NITEC_API_KEY`; основной чат отдельно требует `ANTHROPIC_API_KEY`. API загрузки синхронно ждёт распознавания, поэтому сканы и аудио могут отвечать дольше обычного чата. Кеш защищает от повторного вычисления; многопроцессорный воркер и автоочистка данных пока не реализованы.

Для проверки загрузите тестовые файлы из `backend/tests/fixtures/`: `spec.docx` и `spec.xlsx` должны показать найденные артикулы, `spec.pdf` — текст и координаты слов из текстового слоя, `photo.png` — OCR через выбранный провайдер. Для проверки аудио загрузите свой файл `.m4a` или `.wav`. Фото, сканы PDF и аудио расходуют API-кредиты; повторная загрузка идентичных байтов с той же моделью читает кеш.

## Архитектура прототипа

Виджет отправляет сообщения и вложения в FastAPI. `attachments.py` хранит исходные файлы, извлекает строки спецификации и кеширует распознанный текст; `recognition.py` выбирает локальный парсер, OpenAI или NITEC. `catalog.py` использует локальный индекс для поиска, а перед ответом о наличии и при подтверждении корзины backend запрашивает актуальные данные EKT API. `agent.py` формирует консультацию, `cart.py` хранит предложенное действие отдельно от корзины и применяет его только после подтверждения. Локальный `/lab` проверяет именно слой распознавания файлов без запуска сценария чата.

## Ограничения прототипа

Для чата нужен отдельный `ANTHROPIC_API_KEY` и собранный индекс каталога. Локальная лаборатория работает без них. Данные и кеш вложений хранятся локально без автоматической очистки; не загружайте реальные персональные документы в публичный стенд. Распознавание может ошибаться на мелком или нечётком тексте; OpenAI OCR не выдаёт проверенных координат, а PDF-сканы обрабатываются максимум на 15 страницах. Ссылка на deployed-версию пока отсутствует.

# Этап 0. Аудит каталога ekt.kz

Отдельный этап подготовки данных — аудит каталога ekt.kz. Его результаты используются для выбора стратегии точного, полнотекстового и семантического поиска.

## Что реализовано

- Возобновляемая выгрузка всех страниц каталога и детальных карточек через API ekt.kz.
- Локальное хранение ответов в SQLite без сохранения API-пароля в файлах проекта.
- Отчёт о полноте выгрузки, покрытии полей и стратегии поиска: [аудит каталога](reports/ekt_catalog_audit.md).

## Как работает текущий этап

Скрипт последовательно читает страницы `/api/products`, сохраняет товары по `id`, затем запрашивает `/api/products/detail?id=…` для каждого товара. Второй скрипт анализирует сохранённые данные и показывает, какие поля подходят для точного, полнотекстового и семантического поиска. При прерывании повторный запуск продолжает с последней сохранённой страницы и недостающих деталей.

## Технологии и архитектура

Python 3 и стандартная библиотека (`urllib`, `sqlite3`, `concurrent.futures`). Внешних Python-пакетов нет.

```text
EKT API → scripts/ekt_catalog_audit.py → data/ekt_catalog.sqlite3
                                         ↓
                        scripts/analyze_ekt_catalog.py
                                         ↓
                         reports/ekt_catalog_audit.md
```

Каталог использует HTTP Basic Auth. Учётные данные вводятся интерактивно или передаются процессу через `EKT_API_USER` и `EKT_API_PASSWORD`. Файлы `.env*` и база в `data/` исключены из Git.

## Установка и запуск

```bash
git clone https://github.com/BAITC-Hacks/hack-59e3f91b-data-hungry.git
cd hack-59e3f91b-data-hungry
python3 scripts/ekt_catalog_audit.py
python3 scripts/analyze_ekt_catalog.py
```

При первом запуске скрипт запросит логин и пароль API. Полная выгрузка делает один запрос на страницу списка и по запросу на каждую детальную карточку, поэтому занимает время. Локальная база `data/ekt_catalog.sqlite3` не коммитится. Для раздельного запуска доступны `--list-only` и `--details-only`; число одновременных запросов деталей задаётся `--workers` (от 1 до 8).

## Как проверить

Для короткой проверки на пустой базе и с выданным организаторами доступом:

```bash
python3 scripts/ekt_catalog_audit.py --db data/check.sqlite3 --list-only --max-pages 1
python3 scripts/ekt_catalog_audit.py --db data/check.sqlite3 --details-only --max-details 10
python3 scripts/analyze_ekt_catalog.py --db data/check.sqlite3 --output data/check-report.md
```

Проверьте в `data/check-report.md`, что получены товары и 10 детальных карточек. Такой тестовый отчёт будет отмечен как неполный.

## Данные и интеграции

Источник — предоставленные для кейса API ekt.kz: список товаров с пагинацией и детальная карточка. В списке доступны название, артикул, цена, URL и изображение; детали добавляют описание, свойства и остатки по складам. Точные показатели по загруженному каталогу находятся в [отчёте](reports/ekt_catalog_audit.md).

## Ограничения

- Скрипты аудита не строят поисковый индекс и не запускают чат; это отдельные компоненты backend.
- Для воспроизведения выгрузки требуются действующие учётные данные API.
- Цена и остатки могут меняться после выгрузки; для ответа покупателю их нужно получать заново.
- Ссылка на развёрнутую версию пока отсутствует.
