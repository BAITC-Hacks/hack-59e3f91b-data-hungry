# Data Hungry — аудит каталога ekt.kz

Проект команды **Data Hungry** для кейса №1 хакатона: «ИИ-ассистент для чата на сайте ekt.kz». Потенциальный пользователь — покупатель электротехнических товаров, которому нужно подобрать позицию по задаче, характеристикам или артикулу. Сейчас в репозитории реализован этап подготовки данных для такого поиска; сам чат-ассистент ещё не создан.

## Что реализовано

- Возобновляемая выгрузка всех страниц каталога и детальных карточек через API ekt.kz.
- Локальное хранение ответов в SQLite без сохранения API-пароля в файлах проекта.
- Отчёт о полноте выгрузки, покрытии полей и стратегии поиска: [аудит каталога](reports/ekt_catalog_audit.md).

## Как работает текущий этап

Скрипт последовательно читает страницы `/api/products`, сохраняет товары по `id`, затем запрашивает `/api/products/detail?id=…` для каждого товара. Второй скрипт анализирует сохранённые данные и показывает, какие поля подходят для точного, полнотекстового и семантического поиска. При прерывании повторный запуск продолжает с последней сохранённой страницы и недостающих деталей.

## Технологии и архитектура

Python 3 и стандартная библиотека (`urllib`, `sqlite3`, `concurrent.futures`). Внешних Python-пакетов нет.

```text
EKT API → scripts/ekt_catalog_audit.py → data/ekt_catalog.sqlite3
                                         ↓
                        scripts/analyze_ekt_catalog.py
                                         ↓
                         reports/ekt_catalog_audit.md
```

Каталог использует HTTP Basic Auth. Учётные данные вводятся интерактивно или передаются процессу через `EKT_API_USER` и `EKT_API_PASSWORD`. Файлы `.env*` и база в `data/` исключены из Git.

## Установка и запуск

```bash
git clone https://github.com/BAITC-Hacks/hack-59e3f91b-data-hungry.git
cd hack-59e3f91b-data-hungry
python3 scripts/ekt_catalog_audit.py
python3 scripts/analyze_ekt_catalog.py
```

При первом запуске скрипт запросит логин и пароль API. Полная выгрузка делает один запрос на страницу списка и по запросу на каждую детальную карточку, поэтому занимает время. Локальная база `data/ekt_catalog.sqlite3` не коммитится. Для раздельного запуска доступны `--list-only` и `--details-only`; число одновременных запросов деталей задаётся `--workers` (от 1 до 8).

## Как проверить

Для короткой проверки на пустой базе и с выданным организаторами доступом:

```bash
python3 scripts/ekt_catalog_audit.py --db data/check.sqlite3 --list-only --max-pages 1
python3 scripts/ekt_catalog_audit.py --db data/check.sqlite3 --details-only --max-details 10
python3 scripts/analyze_ekt_catalog.py --db data/check.sqlite3 --output data/check-report.md
```

Проверьте в `data/check-report.md`, что получены товары и 10 детальных карточек. Такой тестовый отчёт будет отмечен как неполный.

## Данные и интеграции

Источник — предоставленные для кейса API ekt.kz: список товаров с пагинацией и детальная карточка. В списке доступны название, артикул, цена, URL и изображение; детали добавляют описание, свойства и остатки по складам. Точные показатели по загруженному каталогу находятся в [отчёте](reports/ekt_catalog_audit.md).

## Ограничения

- Чат, поисковый индекс, эмбеддинги и интерфейс пока не реализованы.
- Для воспроизведения выгрузки требуются действующие учётные данные API.
- Цена и остатки могут меняться после выгрузки; для ответа покупателю их нужно получать заново.
- Ссылка на развёрнутую версию пока отсутствует.
